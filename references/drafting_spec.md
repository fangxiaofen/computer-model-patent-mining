# 计算机模型类发明专利 · 撰写规范细则

## 1. 法律依据速查

| 条文 | 要点 | 撰写应对 |
|------|------|----------|
| 《专利法》第 2 条第 2 款 | 发明是对产品、方法或其改进提出的**技术方案**：技术手段 + 技术问题 + 技术效果 | 三部分齐全且互相支撑 |
| 《专利法》第 22 条 | 新颖性、创造性、实用性 | 明确最接近现有技术 + 区别特征；效果可验证 |
| 《专利法》第 25 条第 1 款第 2 项 | 智力活动的规则和方法不授权 | 绑定外部技术数据 / 物理过程 / 设备状态改变 |
| 《专利法》第 26 条第 3 款 | 清楚、完整，所属技术领域技术人员能够实现 | 算法步骤写全、参数给规则、不隐藏关键细节 |
| 《专利法》第 26 条第 4 款 | 权利要求以说明书为依据，清楚、简要 | 效果表述与权利要求范围相称，不夸大 |
| 《专利法》第 33 条 | 修改不得超范围 | 初稿即写全，避免后期补入新内容 |
| 《专利审查指南》第二部分第九章 | 涉及计算机程序的发明专利申请审查 | 方法权利要求与装置/介质权利要求对应撰写 |

## 2. 模型类专利的客体合规改造手法（重点）

当创新点偏"算法/模型"时，用下列任一手法把它改造为技术方案：

1. **处理对象技术化**：明确输入为"图像像素数据""振动加速度时序信号""电池端电压与电流采样序列""三维点云""频谱图"，并说明其**物理/技术含义**。
2. **处理目的技术化**：输出用于"故障识别""缺陷检测""剩余寿命预测""设备控制参数调节""路径规划""能耗调度"，而非"评分""排序""推荐"。
3. **技术指标化**：将模型内部改进映射为设备/系统级性能（显存占用 → 端侧可部署性；推理时延 → 实时控制可用性；参数量 → 存储成本）。
4. **硬件耦合化**：写明模型运行于具体硬件（边缘计算单元、嵌入式处理器、PLC、车载 ECU），并随硬件资源约束做结构/精度自适应。
5. **闭环控制化**：模型输出反馈作用于被控对象，形成"感知—推理—决策—执行—再感知"闭环。

**反面示例（不可写）**：「一种基于注意力机制的评分排序方法，通过模型对用户偏好打分实现个性化排序。」
**正面示例（可写）**：「一种基于多尺度注意力加权卷积神经网络的滚动轴承故障识别方法，通过对振动加速度信号的时频特征图进行通道-空间双重加权，抑制噪声频段响应，输出故障类型及置信度，用于触发设备停机保护。」

## 3. 术语与表述规范

### 3.1 术语一致性
- 同一技术特征全篇使用**同一术语**，禁止"特征提取模块 / 特征抽取单元 / 特征提取器"混用。
- 英文缩写首次出现给中文全称：`多尺度特征融合（Multi-Scale Feature Fusion，MSFF）模块`，后续统一用 MSFF。
- 术语与附图标记绑定：`特征提取模块 3`，正文、附图、附图说明三处一致。

### 3.2 推荐句式
- 模块定义：`所述 XX 模块配置为：接收……，执行……，输出……。`
- 步骤展开：`所述步骤 S3 具体包括以下子步骤：S31，……；S32，……。`
- 算法描述：`按照下式计算……：Y = f(X, W)，其中，X 表示……，W 表示……，f(·) 表示……。`
- 参数规则：`取 λ∈[0.1, 1.0]，且 λ 依据验证集上 F1 值最大处确定。`
- 效果表述：`在 XX 数据集、信噪比 0 dB 工况下，故障识别准确率由 78.4% 提升至 91.2%。`

### 3.3 禁用词表（命中即必须改写）

| 类别 | 禁用词 | 替换为 |
|------|--------|--------|
| 营销夸张 | 极大地、极大地提升、革命性、颠覆性、完美、彻底、根本性突破、显著优于一切 | 提升、提高、改善、降低、由 X 变为 Y |
| 模糊不定 | 大约、大概、可能、最好是、适当的、一定的、若干、等等 | 给出具体范围或规则；从属权利要求可用「优选地」 |
| 论文式抒情 | 值得注意的是、令人遗憾的是、不难发现、众所周知、我们希望、毋庸置疑 | 直接陈述事实 |
| 主观评价 | 效果好、性能优越、智能化程度高、用户体验佳 | 给出指标与数值 |
| 绝对化 | 总是、必然、全部、所有情况下均 | 在……条件下、通常、针对…… |
| 无依据比较 | 远优于、数倍于、远超 | 给出同条件基线对比数值 |
| 宣传性命名 | 新型、高效、超级、智能（作宣传用）、新一代 | 中性技术命名 |
| AI 腔 | 综上所述、总而言之、值得一提的是、希望本文 | 删除或改为客观小结 |

### 3.4 数值与单位
- 数值必须带单位或量纲说明；范围用「～」或「至」，端点明确。
- 百分比要说明是**相对提升**还是**绝对百分点**。
- 对比实验必须**同数据集、同硬件、同评测口径**。

## 4. 章节撰写细则

### 4.1 技术问题
- 只写问题，不写解决方案，不出现"本发明"。
- 引用现有技术时使用客观表述："现有方案中，……"，避免贬低。
- 字数严格 300–500。

### 4.2 技术方案
- 八要素齐全（架构 / 模块 / 步骤 / 算法 / 数据 / 参数 / 训练推理 / 联动）。
- 必要技术特征 5–9 条，编号连续，每条一句可概括、一段可展开。
- 公知技术一句话带过并标 `[公知]`；创新技术展开写并标 `[创新]`。
- 每个模块写清**输入数据形态 → 处理 → 输出数据形态**。

### 4.3 技术效果
- 逐条对应，标注痛点与特征编号。
- 量化优先；无数据则定性 + 标注「（推定，待实验验证）」。
- 不作超出说明书记载范围的断言（避免第 26 条第 4 款问题）。

### 4.4 附图说明
- 句式：`图 1 为本发明实施例中 XX 的系统框架示意图；`
- 只列标记与名称，不写功能解释与效果评价。
- 阿拉伯数字编号，与图中一致。

## 5. 常见驳回风险与预防

| 风险 | 表现 | 预防 |
|------|------|------|
| 客体不合格 | 被视为智力活动规则 | 绑定技术数据 + 技术目的 + 技术效果 |
| 公开不充分 | 关键算法步骤缺失 | 步骤写到可复现，参数给规则 |
| 创造性不足 | 特征均为公知组合 | 三步法预判，突出协同非显而易见性 + 消融数据 |
| 不支持 | 效果过大，超出方案 | 效果与权利要求范围相称 |
| 不清楚 | 术语漂移、附图标记错乱 | 术语表 + 标记一致性检查 |
| 超范围修改 | 后期补入未记载内容 | 初稿写全，预设从属层次 |
