# 步骤 7｜组装成稿与闭环自检

## 7.1 组装

按 `assets/output_template.md` 的骨架填装四个部分，前置「发明名称」与「技术领域」，后置「推定与待确认清单」与「自检报告」。

**发明名称**格式：`一种基于<核心创新手段>的<应用领域/对象><方法/系统/装置>`，25 字以内，不含人名、商标、"新型""高效"等宣传词。必要时给 2 个备选名。

**技术领域**：一句，「本发明涉及……技术领域，尤其涉及一种……」，绑定具体工业/技术场景，不写"人工智能领域"这种上位空泛表述。

## 7.2 必跑自检

```bash
python scripts/check_draft.py <成稿.md> --matrix mapping_matrix.csv
```

脚本校验项：
1. 技术问题字数是否在 300–500；
2. 是否缺少任一必需章节；
3. 痛点编号 P* 是否全部被必要技术特征覆盖；
4. 痛点编号 P* 是否全部被技术效果覆盖；
5. 是否存在无痛点对应的孤儿特征/孤儿效果；
6. 是否命中禁用词（营销化、模糊化、论文式抒情）；
7. 是否命中术语不一致（同一英文缩写有多种中文译名）；
8. 是否出现无出处的孤立数字（提示人工核对）。

**任一 FAIL 必须修稿后重跑，直到全 PASS 才交付。**

## 7.3 人工终审清单（脚本之外，逐项确认）

- [ ] 技术问题三层递进且层层深入，无方案泄露
- [ ] 必要技术特征"删一条即不成立"（必要性检验）
- [ ] 创新点与公知技术边界清晰
- [ ] 全部技术内容可追溯至用户资料，推定项已标注并登记
- [ ] 附图标记与正文术语、模块名三者一致
- [ ] 效果数值有出处，无非同类对比
- [ ] 无《专利法》第 25 条客体风险（已绑定外部技术数据/物理过程）
- [ ] 无第 26 条第 4 款支持问题（效果表述与权利要求范围相称）

## 7.4 交付与回显

向用户回显结构化摘要：

```
发明名称：…
核心创新点：…
必要技术特征：N 条
痛点覆盖：X/X（100%）
技术问题字数：XXX 字
附图：图 1 系统框架图（8 个模块标记）、图 2 核心方法流程图（11 个步骤节点）
推定项：M 项（见清单）
自检：PASS / FAIL 项与原因
```

并提示下一步选项：
1. 基于本方案展开**权利要求书**（独立权利要求 + 从属权利要求）；
2. 补写**具体实施方式**（实施例 + 实验例）；
3. 输出**专利检索/查新关键词**与最接近现有技术比对表；
4. 导出 Word / PDF 交付稿。
