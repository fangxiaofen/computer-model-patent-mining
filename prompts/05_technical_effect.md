# 步骤 5｜技术效果（与问题、特征逐条一一对应）

**目标**：让审查员一眼看到——每一个被提出的问题，都被某一个特征解决，并产出了一条**可验证的**技术效果。

## 5.1 对应规则（强制）

- 遍历 `mapping_matrix.csv` 中**全部痛点 P***（含第一层、第二层、第三层每一个），逐条生成一条效果。不得合并、不得遗漏。
- 每条效果开头必须带：
  「**【对应 P1-1｜必要技术特征 2】** …」
- 效果描述结构：`技术手段（简述） → 作用机理 → 效果（量化优先） → 对比对象`。
  示例：
  > 【对应 P2-1｜必要技术特征 3】通过引入通道-空间双重注意力加权，使模型在处理强噪声工况下的振动信号时抑制非冲击频段响应，在 XX 数据集上信噪比 0 dB 条件下的故障识别准确率由 78.4% 提升至 91.2%，相对提升 12.8 个百分点。

## 5.2 效果维度覆盖

按相关性从下列维度选取（不要求全覆盖，但**精度与至少一项工程性指标**必须有）：

| 维度 | 典型量化口径 |
|------|--------------|
| 模型精度 | Accuracy / Precision / Recall / F1 / mAP / AUC / RMSE / MAE |
| 运算效率 | 推理时延 ms、FPS、吞吐量、单轮迭代耗时 |
| 资源功耗 | 参数量、FLOPs / MACs、显存占用、功耗 W、存储体积 |
| 泛化能力 | 跨数据集/跨工况/跨设备性能下降幅度、少样本性能 |
| 场景适配性 | 端侧/边缘可部署性、硬件成本、适配设备型号数 |
| 抗干扰能力 | 噪声/遮挡/光照/缺失数据下的性能保持率 |
| 落地稳定性 | 长时间运行性能漂移、收敛稳定性、故障率、维护周期 |

## 5.3 量化数据来源纪律

1. 有用户资料的实测数据 → 直接引用，注明数据集与条件。
2. 资料只有部分数据 → 引用已有部分，其余用**定性**表述（"显著降低""保持在 X% 以上"），不编造数字。
3. 无任何数据 → 明确写「（该数值为推定值，需经实验验证）」，并在《推定与待确认清单》登记。
4. 禁止：无依据的"提升 30%""效果提升数倍"；禁止跨条件比较（用不同数据集的基线比本方案）。

## 5.4 输出格式

```
## 三、技术效果

### 3.1 与三层技术问题逐条对应
**【对应 P1-1｜必要技术特征 1】** …
**【对应 P1-2｜必要技术特征 2】** …
**【对应 P2-1｜必要技术特征 3】** …
**【对应 P3-1｜必要技术特征 4、5】** …

### 3.2 与现有技术对比汇总
| 对比项 | 现有方案 | 本方案 | 改善 | 对应痛点 |
```

## 5.5 自查清单

- [ ] 痛点覆盖率 100%（跑 `check_draft.py` 校验）
- [ ] 无孤儿效果（每条效果都能追到一个痛点与一条必要技术特征）
- [ ] 量化数据均有出处或已标注「推定」
- [ ] 无营销化词汇（"革命性""极大""完美""彻底"）
- [ ] 至少含精度 + 一项工程性指标（效率/资源/鲁棒）
