# 步骤 3｜技术问题（300–500 字，三级递进）

**目标**：产出严格 300–500 中文字、由浅入深、直指本专利创新必要性的技术问题段落。

## 3.1 三级递进骨架（必须逐级推进，不得跳级、不得平铺）

| 层级 | 写什么 | 素材来源 | 建议占比 |
|------|--------|----------|----------|
| **第一层 · 行业通用缺陷** | 该类计算机模型/通用深度学习方案在本技术领域存在的**共性基础缺陷**（如：依赖大规模标注数据、固定结构难以适配多尺度、算力与精度不可兼得、黑箱不可解释、泛化依赖训练分布等） | 领域常识 + 资料 `G` 中通用性表述 | 90–140 字 |
| **第二层 · 场景化短板** | 结合**本次背景资料的具体应用场景**，点明现有/传统方案在该场景下的**具体技术短板**（把第一层缺陷落到"谁、在什么工况下、出了什么问题"） | `G` 中场景相关缺陷 + `F` 场景约束 | 110–170 字 |
| **第三层 · 核心技术瓶颈** | 聚焦最要害的**技术瓶颈**，说明其导致的落地问题、性能缺陷、应用局限，并明确"当前技术亟需解决的核心难题是什么" | `E` 指标短板 + `C` 算法逻辑矛盾点 | 100–180 字 |

收尾句必须自然引出**本专利的创新必要性**（如："因此，亟需提供一种……的技术方案，以在……约束下同时实现……与……。"）。

## 3.2 写作铁律

1. **字数**：写完后用脚本统计（去空白、去标点外的空白字符）：`python scripts/check_draft.py --count-only <file>`。低于 300 字 → 补充第二层的场景细节；超过 500 字 → 删除第一层的泛泛而谈，保留与后续创新点直接相关的共性缺陷。
2. **不笼统**：禁止"效果不理想""性能较差""难以满足需求"这类无信息量表述。每一句都必须可追溯到一个具体缺陷。
3. **不预支方案**：技术问题段**只写问题，不写本专利如何解决**（解决方案属第二部分）。
4. **不诋毁式夸张**：不使用"完全无法""彻底失败"，使用"难以""受限""显著下降"等客观措辞。
5. **层层递进的连接词**：第一层→第二层用"然而，具体到……场景下，……"；第二层→第三层用"更为关键的是，……""进一步的，上述缺陷的根本原因在于……"。
6. **与三维映射同步**：边写边在 `mapping_matrix.csv` 登记，每个层级拆分出 **2–3 个可命名的痛点**（如 P1-1、P1-2、P2-1……），后续特征与效果按痛点编号一一对应。

## 3.3 输出格式

```
## 一、技术问题

<三级递进正文，自然段连写或分三段均可，随文以「第一层/第二层/第三层」标注层级>

（本部分共计 XXX 字）
```

> 交付给用户时保留层级标注；若用户要求纯正文，去掉标注但**字数不变**。

## 3.4 自查清单（交付前逐项打勾）

- [ ] 字数在 300–500 之间
- [ ] 三层齐全，且层层深入（第二层是第一层的场景化，第三层是前两层的原因/瓶颈）
- [ ] 无解决方案泄露
- [ ] 每个痛点已编号并登记进映射表
- [ ] 无"效果不理想"类空话
- [ ] 末句引出创新必要性
