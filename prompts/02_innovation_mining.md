# 步骤 2｜创新点挖掘与公知 / 创新分离

**目标**：从技术要素表中挖出 **1 个核心发明点 + 2–4 个从属增强点**，并明确划出「公知技术」与「本专利创新技术」的边界。

## 2.1 挖掘四条路径（按优先级依次走）

### 路径一｜缺陷驱动法（首选）
直接读 `G. 现有技术缺陷`。每一条缺陷都是一个候选发明点：
- 资料说"现有模型在小目标上漏检严重" → 候选点：多尺度特征增强 / 难例加权 / 上下文注意力
- 资料说"模型参数量大无法部署到边缘" → 候选点：结构化剪枝 + 量化 + 蒸馏联合压缩
- 资料说"跨工况泛化差" → 候选点：领域自适应 / 归一化统计量解耦 / 自监督预训练

### 路径二｜效果反推法
读 `E. 实验与效果`。凡是**提升幅度最大的那一项**或**唯一显著的那一项**，其背后一定有非常规设计 → 回溯到 `C. 算法逻辑` 找到对应设计，即为核心发明点。

### 路径三｜场景反推法
读 `F. 应用场景与约束`。场景硬约束（时延 ≤ X ms、内存 ≤ Y MB、无标注数据、噪声/遮挡/光照变化、需实时闭环控制）与现有通用模型之间的**矛盾点**，即创新空间。

### 路径四｜组合重构法
若单项设计均较常规，则考察**组合协同**：A + B 的组合是否产生了单独使用时不具备的协同效果（1+1 > 2）？组合型发明点的创造性论证要点是**协同非显而易见性**，必须在技术效果中给出消融对比支撑。

> 挖掘切入点速查：`references/innovation_playbook.md`（八大切入面：数据 / 结构 / 损失 / 训练策略 / 推理部署 / 优化求解 / 后处理 / 场景耦合）。

## 2.2 客体合规体检（必做，规避《专利法》第 25 条）

对每个候选发明点自问三题，任一为「否」即整改：

1. **是否解决技术问题**（而非数学问题/商业问题/主观评价问题）？
2. **是否采用技术手段**（利用符合自然规律的技术手段）？
3. **是否产生技术效果**（可量化/可验证的技术性能改变）？

整改手法（模型类专利的标准规避路径）：
- 将算法处理对象明确为**外部技术数据**（图像像素、振动信号、电池电压/电流时序、点云、频谱等），并说明数据的**技术含义**；
- 将模型输出用于**控制物理过程/驱动执行机构/改变设备运行状态**；
- 将内部指标改进映射为**外部技术性能改进**（显存占用 → 设备可部署性；推理时延 → 实时控制可行性）。

## 2.4 创造性自检（三步法预判）

对每个创新点：
1. 假定**最接近的现有技术**是什么（写出现有方案名或通用做法）；
2. 列出**区别技术特征**；
3. 由区别特征确定**实际解决的技术问题**；
4. 判断：现有技术是否给出将该区别特征应用于最接近现有技术的**技术启示**？若无（或启示指向相反方向），创造性成立。

若结论为"显而易见"，**不得**作为核心发明点，降级为从属增强点或改用组合重构法重新挖掘。

## 2.5 输出回显

向用户回显：核心发明点名称、区别特征、2–4 个从属增强点，并提示「如与创新方向不符请在此处指出，后续步骤将据此重挖」——**只在此处给用户一次纠偏机会**，之后不再打断。
