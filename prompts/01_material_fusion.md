# 步骤 1｜资料融合与技术要素抽取

**目标**：把用户提供的零散资料（项目申请书 / 中英文论文 / 技术文档 / 背景技术资料 / 实验数据）压成一张**结构化技术要素表**，作为后续挖掘与撰写的唯一事实来源。

## 1.1 输入归集

通读全部资料，按下列类别建档（缺失项写「缺」并在《推定与待确认清单》登记）：

- `A. 技术来源`：项目申请书 / 已发表论文（注明是否公开、公开日）/ 内部技术文档 / 竞品资料 / 标准
- `B. 模型体系`：模型家族、网络骨架、层数/参数量、输入模态、输出形态
- `C. 算法逻辑`：前向流程、损失函数、训练策略、优化器、超参、后处理
- `D. 数据`：数据来源、规模、标注方式、预处理/增强、划分比例、数据缺陷
- `E. 实验与效果`：指标名称、基线、本方案数值、提升幅度、消融实验、硬件环境与耗时
- `F. 应用场景`：部署形态（云/边/端）、硬件平台、实时性要求、工况条件、环境干扰
- `G. 现有技术缺陷`：资料中明确列出的现有方案缺点（**这是技术问题第二/三层的主要素材**）
- `H. 技术术语表`：中英文术语对照（后续全篇统一）

## 1.2 输出格式（写入中间产物，不直接交付用户）

```
## 技术要素表
### A. 技术来源
- …
### B. 模型体系
- 模型家族：
- 骨架结构：
- 输入/输出：
### C. 算法逻辑
- 前向：
- 损失：
- 训练策略：
- 超参：
### D. 数据
- …
### E. 实验与效果（逐条列数值）
| 指标 | 基线 | 本方案 | 提升 | 来源 |
### F. 应用场景与约束
- …
### G. 现有技术缺陷（原始摘录 + 出处）
1. …
### H. 术语对照表
| 中文 | 英文 | 备注 |
```

## 1.3 硬性要求

1. **不许脱离原始资料新增技术内容**。需要补充时，只能补**公知的、为实施所必需的常规手段**（如"采用 Adam 优化器""采用交叉熵损失"），并在输出中归入「公知技术」块。
2. 资料中提到但未写清的技术点，标「（推定）」，登记到《推定与待确认清单》，写明推定依据。
3. 若资料为**英文论文**，须保留原始英文术语并给出中文译名，避免同名术语在后续步骤漂移。
4. 若资料中存在**自相矛盾**的表述（如两处指标不一致），在表中并列标出，并在清单中提示用户确认，不擅自取其一。
5. 抽取完成后，用一句「技术要素表已生成：模型体系 X 项、算法逻辑 Y 项、现有技术缺陷 Z 条、实验指标 W 项」向用户回显。

## 1.4 进入下一步的判定

- 若 `G. 现有技术缺陷` 少于 3 条 → 从 `E`（实验数据反映的性能短板）与 `F`（场景约束）反推补齐，仍不足则进入步骤 2 的「场景反推法」。
- 若 `E. 实验与效果` 完全缺失 → 在清单中明确提示"缺少量化实验数据，技术效果部分将仅作定性描述并标注（推定）"，**不阻塞流程**。
